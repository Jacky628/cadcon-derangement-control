## 0. 目的

在一个去重、分层、足量的新留出集上重做已冻结的六格压力测试，把 "wrong-content header 是否使
adherence 跌破无条件基线" 从「不知道」变成一个有功效支撑的确定答案。

现有结论建立在 **38 个唯一程序**上。按冻结检验规格在这 38 个簇上复算，text 侧三个 seed 的功效是
**0.31 / 0.47 / 0.65**，「≥2/3 seeds 显著」的概率只有 **0.463**——预注册判据「没通过」这件事本身
信息量接近于零。

## 1. 评测矩阵

条件模型全部为既有 checkpoint，纯推理，零训练：

| 角色 | checkpoint | seeds |
|---|---|---|
| 条件化-token | `sft_constraint_tokens_seed{0,1,2}` | 3 |
| 条件化-text | `sft_constraint_text_seed{0,1,2}` | 3 |
| 无条件基线 | `sft_no_constraints_seed{0,1,2}` | 3 |

格子结构沿用 C-spike：条件化模型 × {header: correct, shuffled, masked} × 3 seed，加基线 × 3 seed
= **21 个 eval job**。**prefix 维度已裁决为只跑 0.4 一列**（A-5，依据见 §1.1）。

- `shuffled` = `_build_shuffle_plan`（另一真实样本的 well-formed header，内容错误），rng seed 固定。
- `masked` = `eval_mode="none"`（结构性地不属于 `header_source` 维度）。
- 解码：贪心、**bfloat16**（`main.py:1017`；`load_qwen_fp16_for_eval` 的函数名是历史遗留的误称）、
  **`eval_batch_size` = 8（冻结值，A-8）**、`calibrate_generation` 自适应 cap（prefix 0.4 → 474）。
- 作业清单由 `make_repl_jobs.py` 生成并 dry-check：(condition, seed) 无重复、每 job
  `eval_subset_size == 400`、无 `header_source≠correct ∧ eval_mode=none` 的静默降级组合、
  每 condition 恰好 3 seed、checkpoint 全部在盘。

### 1.1 prefix-0 列的有效样本量（v2 新增，决定该列跑与不跑）

prefix=0 时 prompt 里没有代码前缀，只剩 header。header 是 4-tag 组合，非空组合上限 15 种，
加空 header 共 16 种。因此**该列的不同输入数由 header 空间封顶，与抽多少个程序完全无关**。

实测（v1 数据，seed 0，100 条名义样本）：

| 条件 | 唯一 prompt | 唯一生成 | 簇级 SE ÷ 朴素 SE |
|---|---:|---:|---:|
| `baseline_p00` | **1** | **1** | 无定义 |
| `text_masked_p00` / `token_masked_p00` | **1** | **1** | 无定义 |
| `text_correct_p00` | 13 | 12–13 | **2.80 – 3.45** |
| `text_shuffled_p00` | 12 | 13–14 | 1.31 – 1.59 |
| `text_correct_p04` | 39 | 31–32 | 1.53 – 1.58 |
| **`text_shuffled_p04`（主判据格）** | 81 | 62–64 | **1.11** |

在新的 400 程序样本上重算输入侧，结论不变：

| 条件 | v1（100 样本 / 50 程序） | 新（400 程序） |
|---|---:|---:|
| `baseline_p04` | 34 | **298** |
| `text_shuffled_p04` | 81 | **352** |
| `baseline_p00` / `masked_p00` | 1 | **1** |
| `*_p00` correct / shuffled | 12–13 | **19** |

**把样本从 100 加到 400，prefix-0 列的独立信息一动不动；prefix-0.4 列增加约 4–9 倍。**
复制实验的全部统计价值都在 prefix-0.4 列。

这与 v1 §4.1 记录的另一个事实叠加：`baseline_p00` 三个 seed 的可执行率均为 0/100，recall 恒零，
而 recall ≥ 0，所以 "wrong < baseline" 在该列数学上不可能为负——v1 里该列 6/6 触发反向一票否决，
`masked_p00` 的差值恒为 0（检验退化）。

## 4. 判定规则

**分析单位 = 一个唯一 transpile 程序**。v1 需要先在 gt_sha256 簇内平均；新样本由构造保证唯一，
`replication_analysis.py` 对此设断言——不存在可以做错的聚类步骤。

**配对**：一切 Δ 为同 seed 配对，Δ(s) = 条件臂(seed s) − baseline(seed s)，按 idx 逐样本配对。
禁止使用 seed 平均的 baseline。

**冻结检验规格**（与 C-spike 逐字相同）：`scipy.stats.wilcoxon(d, zero_method="pratt",
alternative="less", method="asymptotic")`，p 取原始值不四舍五入，全零差计为不显著，
方向 = mean(d) 的符号。scipy 1.17.1。

**完整判据**（对给定模式、给定 prefix 的 wrong<baseline 比较）：

1. **text**：3 seed 中 mean(d)<0 的 ≥2/3，且 ≥2/3 个 seed 冻结检验 p<0.05；
2. **token**：3 seed 中 mean(d)<0 的 ≥2/3（方向要求，不要求显著）；
3. **反向一票否决**：任一 seed、任一模式反向检验 p<0.05 → 判据不成立；
4. **profile 级方向护栏**：text 在该 prefix 的 profile 级 mean 效应点估计 ≤0。
   **裁决（A-4）：只计入 n≥15 的 profile**，等权平均；11 个 profile 中 10 个计入，
   CIRCLE+NGON+TALL（n=6）只报点估计不进护栏。理由是让一个 6 程序的 profile 与 112 程序的
   THIN 同权，会让它的噪声单独扳动护栏。实现见 `replication_analysis.py:GUARDRAIL_MIN_PROFILE_N`。

**非零计数护栏**：每 seed 非零配对差数 < **60**（= 0.15n）的 seed 标 underpowered。v1 的绝对阈值
15 是按 n=76 定的。**可执行化**：若某判据的 ≥2/3 多数在剔除 underpowered seed 后不再成立，
该判据不成立（附录 A-3）。

### 4.5 `eval_batch_size` 是实验参数，不是性能旋钮（v2 新增）

实测（附录 C）：贪心解码**不是 batch 不变的**。同一批 prompt 在 batch=8 与 batch=32 下，
生成逐字节相同的比例只有 78%（prefix 0.4）；batch=8 vs 16 在 prefix 0 的 text 臂只有 56%。

**机制已由对照实验钉死：来源是 left-padding，不是批维度本身。** 用一组长度完全相同的 prompt
（`baseline`、`eval_mode=none`、prefix 0，全部恒为 `"\n"`，因而不产生任何 padding）重跑
batch=8 与 batch=32，结果 **32/32 逐字节相同**——而该对照用的是 cap=750 的长生成，同时排除了
「生成越长越容易发散」这一混淆。bf16 下 padding token 改变了 attention 归一化的数值路径，
处在 top-1/top-2 边界的 token 因此翻转，一旦翻转后续整段发散。

由此得到干净的处置：**固定 `eval_batch_size` + 固定样本顺序 → 固定分批 → 固定 padding → 完全
确定**。冻结样本数据集已保证顺序，故只需冻结 batch size。

**裁决（A-8）：`eval_batch_size` 冻结为 8**，与 v1 协议同值，不引入新自由度。batch=32 可使
GPU 部分快约 4 倍且经 C-4 实测对主度量影响有限，但本实验不赶档期，省下的时间不值得在协议
一致性上多一个需要解释的偏离。§10 钢铁条款禁止运行开始后改动此值。

因此：

- `eval_batch_size` 必须在本文档中冻结，并对全部作业取同一值；
- 它的取值不影响比较的公平性（同一值作用于所有臂），但影响结果的逐字节可复现性；
- 主度量对它的敏感度实测见附录 C，取值建议见附录 A-8。

### 4.45 总体定义与加权敏感性分析（裁决 A-2）

分层抽样使样本的 profile 混合不等于 DeepCAD 留出集的自然分布（TALL 系合计 51/400 = 12.8%，
自然比例 8.6%）。**主分析对 400 个程序不加权**，因此推断的总体是「profile 平衡的总体」，
论文须如此表述。

**同时报告**一个按清洁池 profile 比例加权的版本作为敏感性分析（`c4_extras.pool_weighted_mean`），
用以直接回答「结论是否被过采样的稀有 profile 驱动」。该值**只报告、不改判据**。

### 4.55 新样本上的生成截断率（v2 新增，事前记录）

实测：同一 checkpoint（`sft_constraint_text_seed0`）、同一条件（text / correct / prefix 0.4），
新的 400 程序池上生成撞到 `max_new_tokens` cap 的比例是 **0.210（7/7 批有截断）**，而 v1 老池上
是 **0.045（7/39 批）**——高 4.7 倍。`masked` 臂在老池上是 0.000。

不是 GT 变长所致：新样本中只有 2.3% 的 GT 尾段超过 474 token。是**模型在新样本上更常不产生
EOS**，最可能的原因是新样本覆盖了 v1 完全没有的 5 个 profile（§2.2），模型在这些上更易发散。

三点处置：

1. **不调 cap**。cap 由 `calibrate_generation` 从 train 样本的 completion p95 导出（prefix 0.4 →
   474，prefix 0.0 → 750），与 v1 同一规则。既然截断的主因是模型发散而非程序长度，提高 cap 只
   会更慢而救不回这些样本；截断在此处是合理的截止点。
2. **绝对水平不可与 v1 逐格比较**。执行计入式主度量下，截断产物大概率执行失败而记 0，因此新
   样本上各臂的 recall 绝对值会系统性低于 v1。这对**所有臂一致**，配对比较不受影响，但论文中
   不得把新旧两套数字并排当作同一尺度。
3. **功效仍充足**。额外约 16.5 个百分点的样本可能因此变成零差值，把 v1 观测到的 33% 非零比例
   稀释到约 27.5%；§8 的功效表在稀释到 20% 时仍为 0.988、13% 时 0.938，故本设计有余量。
   非零计数护栏（60 = 0.15n）同样有余量。

### 4.6 in-loop oracle 的处置（v2 新增）

`eval_validity` 内对每个样本串行调用 `run_cadquery_oracle`（子进程，10 s 超时），实测占单作业
墙钟约 **13%**（11–16%），且 16 核机器上只用 1 核。它的 valid 位**不进主判据**（§3），只进
`validity_rate` 报告。可以并行化（纯函数、无共享状态，先并行求值再串行走记录循环，输出顺序
逐字节不变）。这不触碰任何生成语义，也不改变任何被判据读取的数字。

**裁决（A-9）：实施，并发度 6**（`ORACLE_WORKERS`，可用 `ARC_ORACLE_WORKERS=1` 回退串行）。
6 是在 16 核上留足余量的取值——两个作业同时在飞时共 12 个 oracle 进程，使单个程序不会仅仅
因为机器繁忙而撞上 10 s 超时（实测单程序 1.8–2.9 s，离群值 5.9 s）。验收要求是**逐位不变**：
对 256 条真实生成程序，并行与串行的 valid 位序列必须完全一致，结果见 §11.6。

## 6. 两种结局的论文写法（已定稿，A-6）

本节在任何评测数据存在之前定稿。两种结局的写法一经冻结即不得互换，也不得在事后新增第三种
表述——这是本预注册防止事后择优的核心条款。

**text 复制成功**（`shuffled_p04` 判据通过）：主张回到 "wrong intent is worse than none"。
因果对照（f4 R 臂 derangement）与推断证据同在 text 臂，原先「因果对照在 text 臂、推断证据在
token 臂」的表面形式错配消失；预注册判据在有功效的样本（n=400，功效 1.000）上通过。论文重心
从「评测审计」回到「CAD 风险发现」，评测审计降为方法节。

按 A-5 不跑 prefix-0 列，故正文与摘要沿用既有的 regime 限定表述（效应属于 conditional-completion
设定），并补一句说明：该限定在本次复制中未重测，因为 prefix-0 列的有效样本量由 header 组合数
封顶（≤19），与抽取的程序数无关（§1.1）——即重测不会带来新信息，而非回避。

同时须报告：新样本上各臂 recall 的绝对水平低于 v1（§4.55 的截断率差异），故新旧数字不得并排
当作同一尺度；以及 §4.45 的池加权敏感性分析结果。

**text 复制失败**（`shuffled_p04` 判据不通过）：这是一个**有功效的干净阴性结果**，比现状
（功效 0.463、什么都说明不了）强得多，必须如此呈现，不得淡化为「未能确认」。

此时：(i) token 侧的 derangement 对照成为必做项，否则 "wrong<none 依赖 tokenization" 这一
主张缺因果支撑；(ii) 该依赖性本身是值得报告的发现——伤害只在 token 条件化下成立，说明它与
表示形式绑定而非语义普遍性质；(iii) 论文改为报告：在 400 个去重、profile 分层的程序上，
text 条件化模型对错误 intent 的脆弱性不成立。

若 token 侧判据通过而 text 侧不通过，标题与摘要须写成 tokenization-specific 的主张，
不得保留任何暗示该效应普遍成立的措辞。

## 8. 功效

从 v1 冻结数据取观测到的簇级配对差，按复制实验实际会抽到的 profile 混合重采样（v1 缺失的 5 个
profile 用全体差值的经验分布代替），跑冻结检验规格，2000 次模拟：

| 情形 | text 三 seed | P(≥2/3 显著) |
|---|---|---|
| v1 实际 n=38 | 0.31 / 0.47 / 0.65 | **0.463** |
| n=400，v1 profile 混合 | 0.99 / 1.00 / 1.00 | 1.000 |
| n=400，**分层混合（本设计）** | 0.99 / 0.98 / 1.00 | **1.000** |
| 分层混合，效应比例稀释到 20% | 0.91 / 0.87 / 1.00 | 0.988 |
| 分层混合，效应比例稀释到 13% | 0.77 / 0.73 / 1.00 | 0.938 |

token 侧在所有情形下均为 1.000。分层过采样稀有 profile 没有稀释功效。

风险模型是「出现效应的程序比例下降」而非「效应幅度变小」——Wilcoxon 是秩检验，等比缩放不改变功效。

**该功效计算的单位是程序（输入侧）**。§1.1 的产出侧簇分析显示，主判据格 `shuffled_p04` 的产出侧
多样性最高（v1 上 62–64 个唯一生成 / 76 条），簇级 SE 只比朴素 SE 大 1.11 倍，因此该格的功效
结论不因产出侧非独立性而实质改变。prefix-0 列则完全相反（见 §1.1），这是 A-5 的依据。

## 9. 时间盒

**机时（按 08-06 实测重算，附录 C）**：v1 文档写的 46 h 来自对 20 样本冒烟的线性外推，高估约
28%。根因是成本按**批**而非按样本计——`generate` 要等批内所有序列出 EOS 或撞 cap，20 样本
= 8+8+4 三批，那个半批耗时接近满批，使「每样本秒数」这个口径系统性偏高；400 样本是 50 个满批，
无此浪费。

| 配置 | 42 作业（含 prefix-0 列） | 21 作业（仅 prefix-0.4） |
|---|---:|---:|
| `batch=8`，oracle 串行 | 34–38 h | 14–17 h |
| **`batch=8`，oracle 6 路并行（本次冻结配置）** | 30–33 h | **11–14 h** |

裁决后的实际配置是右下格。逐样本成本 = GPU 9.34 s（实测，新池）+ oracle 4.29/4.22 ≈ 1.02 s，
单作业约 90 s 固定开销 + 400 × 10.36 s ≈ 1.18 h；21 作业双卡 11 轮 ≈ 12.9 h。区间的上沿留给
两个作业同时在飞时的 CPU 争用（12 个 oracle 进程 + 2 个生成进程 / 16 核），下沿留给 masked 臂
——它在 v1 上截断率为 0，是最快的一档。

prefix-0 列占全 run 的 54–61%，按 A-5 不跑。`batch=32` 可使 GPU 部分再快约 4 倍，按 A-8 不采用。

时间盒：计时起点 = 全量发车时间戳（落日志），硬上限 **5 天**。超时 → 报告写明「既未证实也未证伪」，
不得从不完整矩阵出任何方向的裁决。若作业已全部完成而打分/分析未完，允许 +48 h 仅打分与分析延期。

## 11. 发车前检查（v2 新增，全部为已实现的自动断言）

1. `--frozen-list` 绑定：worker 校验注入的 clean-test cache 的程序哈希序列与
   `replication_frozen_lists.json` 逐位一致，且 `eval_subset_size == n`。实测：指向 400 行的
   冻结样本通过，指向 4,641 行的池被拒（`4641 vs 400 rows`）。
2. 留出集重复护栏：注入的 cache 若含重复程序则拒绝发车。实测对 v1 旧 cache 正确报出 4,801 个重复。
3. worker 侧 oracle canary：`oracle_self_test()` 在每个 job 开头执行。此前该自检只在 `main()`
   中调用，`run_dualgpu` 的 worker 路径从不经过，一个冷启动或损坏的 CadQuery/OCP 状态会表现为
   validity 0.000 这种「看起来像结果」的输出。
4. 作业清单 dry-check：见 §1。
5. 冒烟：3 作业 × 20 样本（附录 C），结果丢弃不进分析。
6. **oracle 并行化的逐位验收**（A-9 的放行条件）：对 256 条真实生成程序，串行与 4/6/8 路
   并行的 valid 位序列必须完全一致。实测全部 **0 翻转**；串行复跑亦 0 翻转（排除 oracle
   自身不确定）。6 路实测 506.2 s → 120.1 s（**4.22×**）。脚本 `verify_oracle_parallel.py`。

## 12. 暂停与恢复

**粒度是作业级。** `run_dualgpu.py` 的 `_done_keys()` 读 merge 目录的 `partial_results.jsonl`，
把已有记录的 `(condition, seed)` 全部跳过，因此中断后用**同一条发车命令**重新起即可继续。

- **暂停**：`pkill -f run_dualgpu.py`（orchestrator 与其 worker 一并终止）。
- **继续**：重跑 §1 的发车命令，不要改 `--merge-dir`。
- **代价**：正在飞的至多 2 个作业整个重跑（各约 1.2 h，双卡并行故墙钟损失约 1.2 h）。
  没有样本级恢复。
- **不要**在中断后改动任何冻结件或 `eval_batch_size`——§10 钢铁条款照旧适用。

**写序（发车前修正）**：合并单个作业时，`partial_results.jsonl`（即 resume 标记）写在
adherence 数据**之后**，并在写标记前校验行数与 `metrics.total_count` 一致。原先的顺序是标记
在前，一旦进程在两者之间被杀，该格会被标记为完成却缺失或截断数据，而下游没有任何断言能发现
——分析只检查条件是否存在，不检查它是否携带全部 n 行。倒过来之后，最坏情况是重跑一次并追加
重复行；重复是良性的：固定 batch 下贪心解码确定（实测两次 batch=8 运行在 64 个程序上逐位
一致），`build_scores` 以 `(condition, seed, idx)` 为键，重复行折叠为同一单元。

验收见 `replication_frozen/verify_resume.py`：正常合并、数据不全时拒绝标记、重启只剩未完成
作业、重复合并后仍归并为 400 个单元——四项均通过。

## 13. 扩样规则（增补，冻结于 2026-08-06，判据结果未知时）

**动机**：产物审查（RUN_LOG.md）量化出三条削减有效样本量的机制——提取器在 22.1% 的行上丢弃
模型生成、前缀泄漏 17.8%、400 个程序仅 298 个不同前缀。三者均对所有臂对称，因此不偏倚，但
都在增加配对差为零的样本。本节在**任何方向或 p 值被计算之前**固定「是否以更大样本重做」的
规则，使该决定不受结果影响。

### 13.1 为什么必须现在定

依非零计数调整样本量属于**盲态样本量重估**：非零计数是 nuisance parameter，与效应方向无关，
据此调 n 不膨胀 I 类错误率。而看过方向或 p 值之后再扩样是 **optional stopping**——等于做了
两次检验只报有利的一次，名义 α=0.05 会实际膨胀。两者的差别完全在时序，不在动机，所以规则
必须在开盲之前落定。

### 13.2 规则（可执行，无解释空间）

几何打分完成后、`replication_analysis.py` 运行**之前**，执行
`blinded_power_check.py`。该脚本只计算配对差的非零计数，**代码中不存在计算 mean、符号、
Wilcoxon 或任何方向的路径**——盲态由工具保证，不依赖执行者自律。

- **触发条件**：主判据格 `shuffled_p04` 的**任一模式**（text 或 token）中，3 个 seed 里有
  **≥2 个**的非零计数低于 60（= 0.15n，与 §4 的非零护栏同阈值）。
  依据：某模式的多数由失守的 seed 构成时，该模式的判据条款（c1 或 c2）不可信，而完整判据
  要求两者同时成立。
- `masked_p04`（H2 锚点）的非零计数**只报告、不触发**——它是副判定，不决定 C3 是否复制。
- **触发后**：本次 n=400 的结果以「功效不足、不定论」如实报告；扩样为**独立的新预注册实验**
  （n=800），**不与本次 pooling**（pooling 需要事前的 alpha spending 设计，本次没有）。
- **未触发**：判据按 n=400 定稿。**此后不得因结果不理想而扩样**——这一条与触发条款同等
  具有约束力，是本节的要点所在。

### 13.3 扩样若发生，须事前解决的工程细节

追加式扩样（原 400 + 新 400）中 `correct` / `masked` / `baseline` 三臂的已有结果可复用：
分批是 `range(0, n, 8)`，在末尾追加样本不改变前 50 批的构成，固定 batch 下贪心解码确定，
生成逐字节相同。但 `shuffled` 臂不可复用：`_build_shuffle_plan` 对全部 n 个样本一次性构造，
n 改变则 rng 消耗顺序改变，plan[0] 即不同。新预注册须为新增样本指定独立 rng 流，或声明全部
重跑。

### 13.4 当前证据（记录用，不构成豁免）

发车后 6.6 小时、13/21 格完成时的 regex 口径诊断（非判据格，不含 baseline）：非零配对差比例
`correct vs shuffled` 43.2–49.2%、`correct vs masked` 63.5–66.0%、`shuffled vs masked`
34.2–36.2%，均高于 v1 判据格的 32–34%；绝对非零数 137–264，对阈值 60 有 2–4 倍余量。
据此**预期不会触发**。此段仅为记录，规则的执行以几何口径的实际计数为准。

**C-4 batch 对主度量的影响**（`sft_constraint_text_seed0`、text、prefix 0.4、64 个冻结样本；
主度量口径 = 4-tag 执行计入式 recall，脚本 `score_batch_effect_primary.py`）：

| 对比 | 文本逐字节相同 | 主度量逐样本相同 | mean recall 位移 | validity 位移 |
|---|---:|---:|---:|---:|
| `8_runA` vs `8_runB`（同 batch 复跑） | **64/64** | **64/64** | **0.0000** | 0.0000 |
| 8 vs 16 | 56/64 | 62/64 | −0.0234 | −0.0312 |
| 8 vs 32 | 50/64 | 62/64 | +0.0078 | 0.0000 |

1. **同 batch 复跑逐位相同**，确认抖动完全由 batch 引入，评测本身无随机性。
2. **主度量比文本鲁棒得多**：文本差 22% 时主度量只差 3%——主度量只看 4 个 tag 的有无，

## 附录 E：论文层面的一个待披露项（不属于本预注册，但由同一实测引出）

论文对 prefix-0 列的**主判据**表述是诚实的（摘要与 §4 明写 "wrong < none is undefined when
none cannot generate at all"）。但两处基于 prefix-0 的**正面**主张写的是 100 个观测，而产出侧

- §4.4「masked, the same model … realizes zero intent (0.000)；96/100 和 100/100 outputs run」。

预注册的冻结范围内。**
